# 复查清单

开发前按这份清单做跨文档复查。

执行责任：AI 应主动执行复查，输出问题汇总文档或问题列表；用户负责确认每个问题的处理结论。不要等用户逐项手工检查后才开始复查。

建议输出格式：问题标题、影响文档、位置、级别、问题描述、建议修改、当前状态。

## 范围

- 需求目标和模块设计一致。
- 不做事项没有混入当前阶段设计。
- 验收标准能被模块设计覆盖，或明确暂缓。
- 后续阶段能力没有误写进当前阶段实现。

## 命名

- 模块名、文件名、包路径、接口路径、表名、Tool 名称一致。
- 请求和响应示例的字段命名一致。
- 数据库 snake_case 与代码 camelCase 映射明确。

## 数据

- 表、实体、DTO 对字段类型、必填、默认值、状态含义的描述一致。
- 逻辑删除、状态流转、审计字段、时间字段、用户归属没有被混用。
- 索引能支持文档描述的查询方式。

## 接口

- HTTP 方法和路径风格一致。
- 请求响应示例匹配统一响应格式。
- 用户身份来源明确。
- 分页、排序、筛选规则在需要时被说明。

## 模块边界

- 依赖关系符合设计总览。
- 共享能力放在公共上下文或公共模块。
- 模块文档不依赖隐藏的跨文档知识。

## AI、Tool 和 Prompt

- Tool 名称、参数、返回值与实现设计一致。
- Prompt 说明了什么时候调用 Tool，什么时候不调用。
- 示例回复中没有混入内部注释。
- 注入 Prompt 的对话状态有明确数据来源。

## 开发就绪

- 每个模块都有足够的路径、类名、方法、接口或数据细节。
- 关键边界情况被列出。
- 验证方式或验收点清楚。
- 未解决问题要么已解决，要么明确阻塞。
